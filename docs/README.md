## 建议的讲述顺序

1. 用一分钟说明项目用途、业务边界和主要设计。
2. 从查询商品、选 SKU、试算、同步建单讲一条正常请求。
3. 解释高压力下的可靠异步：PROCESSING、Outbox、消费幂等与补偿。
4. 换成 Agent 入口，说明工具和用户确认为什么共用相同业务服务。
5. 选一个故障，讲清持久化依据、重试规则和当前限制。

## 八个自测问题

| 追问 | 阅读位置 |
|---|---|
| 缓存有价格库存，下单为什么还查数据库？ | 商品查询、接口流程 |
| 锁过期会不会重复建单？ | trace 与幂等 |
| 明天再次购买相同商品，怎么避免误去重？ | trace 与幂等 |
| 为什么 Lua 前先保存 RESERVING？ | 下单设计、消息与恢复 |
| 数据库提交后进程在发 MQ 前崩溃，怎么办？ | 消息与恢复 |
| 消费者正常返回是否证明订单成功？ | 下单设计、测试与压测 |
| 模型说“已下单”能相信吗？ | Agent 设计 |
| 哪些能力还没有完成，性能数字怎么限定？ | 整体架构、测试与压测、面试讲述 |

回答围绕：**遇到什么问题 → 请求怎么走 → 靠什么保证 → 失败怎么办**。未来新增内容直接维护对应主题；测试结果继续合入同一篇，不另建多份版本报告。
