# 为异步建单设计 RocketMQ 事务消息

## Why

当前异步受理把 trace 和建单 Outbox 一起写入，然后在数据库提交后立即尝试发送。定时转发补发，死信恢复也使用同一条 Outbox。事务消息可以评估为一条可选发送路径，收益需要用同样的压测基线验证。

## What Changes

事务消息使用与原建单相同的 `eventId`、标签和 JSON。受理状态、提交证据和原消息共同落库。回查按消息身份读取提交证据，定时转发保留给不确定投递、死信重发、历史建单消息和其他订单事件。

旧 Outbox 发送路径作为默认和回退。按环境灰度，单笔购买固定发送路径。Agent 外层确认仍走已验证的 Outbox 路径，直到独立验证事务消息可等待外层事务完成。

影响能力为 `order-messaging` 和 `order-submission`。此变更仍是提案。
