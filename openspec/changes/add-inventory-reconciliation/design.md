# 库存数量与证据核对

## 统一口径

`product_sku.stock` 已是 MySQL 可售量。建单时在同一 SQL 中扣减 `stock` 和增加 `locked_stock`，所以 `locked_stock` 只作为排查数据展示。Redis 在预占时已经扣过可售量，`CONFIRM` 只推进 Hash 状态。

同一观察窗口内，期望 Redis 可售量按以下口径计算。

```text
期望 Redis 可售 = MySQL.stock
                - Redis 已扣且 MySQL 尚未扣的有效占用
                - MySQL 已关单返库且 Redis 尚未返还的数量
差异 = 实际 Redis 可售 - 期望 Redis 可售
```

第二行包含仍占着 Redis 库存的失败待释放购买。第三行只统计数据库关单已返库、Redis 对应预占仍为 `RESERVED` 或 `CONFIRMED` 的任务。用订单关联、trace 状态、关单返还任务和 Redis 状态交叉判断，同一笔 SKU 占用最多计一次。Redis 已返还但返还表尚未来得及标完成时，以 Redis 的 `RETURNED` 识别返还已经反映。

| 场景 | MySQL 可售 | 在途调整 | Redis 可售期望 |
|---|---:|---:|---:|
| 初始库存 | 10 | 0 | 10 |
| 预扣 2 件，未建单 | 10 | −2 | 8 |
| 建单已提交，Redis 等待确认 2 件 | 8 | 0 | 8 |
| 建单已确认 | 8 | 0 | 8 |
| MySQL 已关单返还 2 件，Redis 待返还 | 10 | −2 | 8 |
| Redis 已返还，SQL 整理进度待更新 | 10 | 0 | 10 |

## 读取与告警

1. 按已初始化 SKU 游标分页。Redis 使用限批扫描，发现预占键时允许重复并去重，批量查对应 trace、订单和返还任务。未初始化 SKU 可以缺少可售键。旧订单按现有 `legacy:` 关联核对。现有 Hash 只有数量和状态，孤儿项的首次发现时间由对账记录维护。
2. 跨 MySQL 和 Redis 无法取得单一原子快照。按限时批次采样，检查批次前后的库存和处理进度。发生变化、扫描未完成、找不到关联或证据冲突时，标记待复核。连续采样仍有差异时报告疑似异常，停流核对可确认实际差异。阈值只决定告警级别，所有可计算的非零差异均记录。
3. 第一版只更新观测结果。正常 `CONFIRM_PENDING` 计量按现有整理任务处理。运维确认后通过持有相应锁的恢复入口处理单笔任务。
