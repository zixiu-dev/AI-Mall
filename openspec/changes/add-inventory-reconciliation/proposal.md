# 增加只读库存对账

## Why

MySQL 可售数和 Redis 可接单数在预扣、建单和关单期间可能短暂不同。库存差异需要能解释到在途交易，并把缺数据和无法核实的情况留给排查。

## What Changes

增加分批只读对账，输出 SKU、双方可售数、在途数量、差异方向和证据状态。已初始化库存池缺失与可核实数量差异分别告警。只有预占记录缺失、旧记录无法关联或高并发期间证据不完整时，记录待复核并再次采样。

第一版只写对账日志和指标。现有库存恢复流程继续负责确认、释放和返还。库存池重建、数据修复和终态 Hash 清理需要单独设计和验证。

影响能力为 `inventory-reservation` 和 `observability`。当前为提案，线上交易仍使用现有库存恢复任务。
