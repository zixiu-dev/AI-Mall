# 缓存防护顺序与分布式重建

## MODIFIED Requirements

### Requirement: CACHE-002 穿透防护

系统 SHALL 在缓存未命中后、申请重建锁之前检查存在性，能够明确否定商品 ID 时避免锁竞争和数据库回源；对可能存在但实际查不到的详情保存短期空结果，过滤器未知时不得错误拒绝合法商品。

#### Scenario: 明确不存在

- **GIVEN** 存在性过滤已就绪并判断 ID 不存在
- **WHEN** 发生该详情的缓存未命中
- **THEN** 直接返回无商品，不申请缓存重建锁、不读取数据库。

#### Scenario: 过滤器误判

- **GIVEN** 过滤判断可能存在但数据库没有该商品
- **WHEN** 读取详情
- **THEN** 保存短期空结果，重复查询在有效期内不反复回源。

#### Scenario: 过滤不可用

- **GIVEN** 存在性过滤未就绪或故障
- **WHEN** 查询合法商品
- **THEN** 继续受保护的读取路径，不直接当成不存在。

#### Scenario: 本地命中不额外查询存在性

- **GIVEN** 公共详情在有效的本地缓存中命中
- **WHEN** 查询同一商品
- **THEN** 直接返回，不为存在性过滤额外访问共享 Redis。

### Requirement: CACHE-003 并发重建与过载保护

系统 SHALL 对同键并发未命中合并重建，在获得跨实例重建执行权后再次检查缓存，并限制回源并发和等待时间；合法长回源支持锁续期，失去执行权的旧查询不能覆盖新结果。

#### Scenario: 多实例重建同一商品

- **GIVEN** 多个实例同时访问同一冷详情
- **WHEN** 一个实例已完成重建并回填
- **THEN** 等待者能够复用新缓存，不必各自重复回源。

#### Scenario: 回源资源不足

- **GIVEN** 等待或回源并发已经达到配置上限
- **WHEN** 新请求继续到达
- **THEN** 有界等待或返回服务繁忙，不能无限累积数据库读取。

#### Scenario: 长回源与失去执行权

- **GIVEN** 缓存回源耗时超过普通短租约，或原持有者因异常失去锁
- **WHEN** 其他实例竞争同一重建任务
- **THEN** 正常持有者续期避免重复构建；旧持有者恢复后不能覆盖新所有者数据或解开他人的锁。
