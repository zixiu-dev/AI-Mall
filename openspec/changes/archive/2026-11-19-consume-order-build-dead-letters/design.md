## 消费入口

独立集群消费组从原建单组的 `%DLQ%<group>` 订阅 `ORDER_BUILD`。首次从最早可用位点读取，后续沿用该消费组位点。建立共享开发 Broker 的应用默认关闭该订阅，确认消息、MySQL 和交易 Redis 属于同一环境后显式启用。

消费者解析原 `traceId` 和消息 Key 内的 `eventId`。在恢复事务内锁定购买记录，确认是已受理过的异步购买，并核对原 Outbox 身份及类型。无法对应的消息记录 Broker 消息编号和异常类型后结束；交易状态和库存均由已匹配的原命令驱动。

## 恢复事务

复用 `OrderRecoveryService`。尚有效时继续使用原 Outbox 的发送间隔；超时且仍未完成时写 QUEUE_TIMEOUT；成功与失败终态各自处理待确认或待释放库存。与建单、定时扫描争用同一 trace 行锁。Redis 整理异常留下原持久化进度，由扫描继续；MySQL 查询或提交异常抛出，由 Broker 重试死信处理。处理重试仍失败的消息汇入独立组自己的死信 Topic，运维可按组定位，现有扫描照常。

监控继续使用 Broker 原生计数；消费者无权解释告警为购买最终失败。第一版不增加人工按单查询入口、消费回执表或第二套建单事务。
