# 设计

一轮以后台助手消息 ID 标识，使用显式携带到聊天工作线程的轮次上下文。按进入步骤顺序分配序号，模型同一步内按实际尝试编号，不创建 loop 表。每条模型调用保存耗时、首段文字时间、错误码和可取得的 Token。工具执行项关联触发模型调用的同轮序号。工具在通过上下文、参数和技能校验后进入业务分发时才计数，查询重试仍在原执行项中累计。确认卡恢复用单独事件关联原编号。

完成后将不含正文的明细放入有界队列，单独线程短批次写两张表。队列拒绝、写库失败或关闭丢弃有独立计数，不在请求内写诊断表。查询读取近期已落库的部分，允许空或不完整。过期读取立即排除；按时间索引分批删除。模型/工具聚合指标沿用 Prometheus，明细 ID 不作指标标签。

GET /api/agent/messages/{messageId}/execution 复用当前后台回答归属校验，返回助手状态和按同轮序号排序的明细。只跟踪主商城后台入口及其 Spring AI 工具循环；兼容聊天、RAG 内部模型和后续确认交易不复制到这一轮。保留确认卡编号，可继续查业务状态。
