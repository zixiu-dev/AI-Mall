## 监控来源

应用定时对异步 trace 做只读聚合。PROCESSING 的年龄从受理时间算起，CONFIRM_PENDING 与 RELEASE_PENDING 从数据库业务结果写入的时间算起。三种积压各自计数。完整采样成功后一起替换内存快照，失败时通过最后成功时间暴露陈旧状态。指标和管理端点只公开聚合数据。

Prometheus 单独抓取 RocketMQ 5.x Broker 的累计死信指标，按建单消费组过滤。规则识别近期增量，也检查初次出现且已有正值的时间序列，覆盖 Broker 首次记录死信时才暴露该序列的情形。监控连接不上时单独告警。

## 业务边界

第一版通过 Broker 指标与 Dashboard 排查，现有恢复任务继续负责有效期内的重投、到期失败和 Lua 幂等释放。Broker 死信不会触发额外下单、改表或改库存，保留原事件编号和购买期限。暂缓逐单查询接口、独立死信表和重放工作台。
