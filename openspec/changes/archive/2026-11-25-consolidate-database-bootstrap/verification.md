# 实际验证

- 三个数据源均使用 Flyway 在临时空库初始化。MySQL、H2 各创建 30 张业务表，初始 757 行与原迁移重放结果一致。默认生成的创建和更新时间按初始化时刻计算。PostgreSQL 创建 3 张向量索引表和 1 行发布指针，与原路径一致。三库空库都只执行建表基线和种子两份 SQL。
- 分别在独立库先执行历史迁移，再用新版两个路径升级。核对旧库修改后的用户昵称和已删除的偏好未被补灌，已发布的 PostgreSQL 索引指针保留。H2 升级测试覆盖旧异步订单迁移保护。
- 旧版本文件移到源码外并保留名称和内容。使用外置目录复跑旧 MySQL、H2 和 PostgreSQL 校验及升级通过。新基线导出的 8 份 MySQL 快照在开启外键检查的另一个空库导入验证通过。PostgreSQL 快照与实际迁移后的索引、约束、注释一致。
- 独立配置执行 `mvn -o -q test`，268 项通过、24 项按环境条件跳过、0 失败。另在临时 MySQL 和 PostgreSQL 上运行真实组件用例，结合 H2 升级用例共 9 项通过。
- 干净目录执行 `mvn -o -q package`，没有历史目录时 265 项通过、27 项跳过，其中 3 项为旧 H2 升级验证。包内每个数据源只有当前建表和种子 SQL。使用 `java -jar` 分别启动 H2 与 MySQL 临时空库，均只执行 B22 和 V23。商品详情、优惠券及 Agent 管理页返回正常。MySQL 重启保留修改后的昵称。
